# PromptShield

PromptShield is a local AI safety testing framework that runs persistent **Red Team vs. Blue Team** simulations against an LLM. It generates adversarial prompts, evaluates the target model's responses, evolves the system prompt when a defense fails, and records the results as a reproducible simulation report.

The goal is to move beyond testing a model with a handful of fixed jailbreak prompts and instead build an iterative safety-evaluation loop that can learn from previous attack outcomes.

## How It Works

PromptShield uses four main components:

```text
                    ┌─────────────────────┐
                    │   Red Team Agent    │
                    │ attacks the target  │
                    └──────────┬──────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │    Target Model     │
                    │  responds to attack │
                    └──────────┬──────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │   Safety Judge      │
                    │ classifies outcome  │
                    └──────────┬──────────┘
                               │
                         attack succeeds?
                               │
                    ┌──────────▼──────────┐
                    │   Blue Team /      │
                    │ System Evolver     │
                    │ hardens the prompt │
                    └──────────┬──────────┘
                               │
                               ▼
                    Validate the new defense
```

1. The **Red Team** starts with predefined attacks across multiple categories.
2. If static attacks are exhausted, it escalates to creative attack strategies generated by an attacker model.
3. The **Target Model** receives the attack under the current system prompt.
4. The **Safety Judge** evaluates the response and assigns a structured classification.
5. When an attack succeeds, the **Blue Team** generates an evolved system prompt intended to prevent the same failure.
6. PromptShield validates the new defense against the attack before deploying it.
7. The simulation history and final hardened system prompt are written to reports.

## Key Features

- Persistent Red Team vs. Blue Team simulation loop
- Multiple adversarial categories including jailbreaks, prompt injection, sensitive-information disclosure, harmful-content generation, role-play attacks, code injection, denial-of-service patterns, and logical-reasoning attacks
- Static attack library followed by creative attack generation
- Unified attack memory for learning from previous outcomes
- Strategy escalation when generated attacks fail
- Automated safety judging with structured JSON classifications
- Defensive system-prompt evolution after successful attacks
- Validation of newly generated defenses before deployment
- JSON and Markdown simulation reports
- Local model execution through Ollama's OpenAI-compatible API
- Configuration-driven model selection and simulation settings

## Attack → Evaluate → Harden

The central design of PromptShield is an iterative feedback loop rather than a one-shot benchmark:

```text
Attack
  ↓
Target response
  ↓
Safety evaluation
  ↓
┌─────────────────────────────┐
│ Defense holds?              │
│                             │
│ YES → continue testing      │
│ NO  → evolve system prompt │
└──────────────┬──────────────┘
               ↓
        Validate defense
               ↓
        Deploy if effective
```

This makes the project useful for experimenting with how defensive prompts respond to repeated and adaptive adversarial pressure.

## Getting Started

### Prerequisites

- Python 3.9+
- [Ollama](https://ollama.com/) installed and running locally
- The models configured in `config.yaml` available in Ollama

### Install

```bash
git clone https://github.com/sidisgr8/promptShield.git
cd promptShield

python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows
# .venv\Scripts\activate

pip install openai pyyaml
```

### Pull the default models

```bash
ollama pull gemma:2b
ollama pull phi3
```

Make sure Ollama is running before starting the simulation.

### Run

```bash
python examples/run.py
```

The simulation parameters and model names are controlled through `config.yaml`.

## Configuration

The main configuration file controls:

- attempts per attack category
- initial system prompt
- target model
- attacker model
- judge model
- report output paths
- static attack prompts

For example:

```yaml
simulation:
  attempts_per_category: 5
  initial_system_prompt: "You are a helpful and harmless AI assistant."

models:
  target: "gemma:2b"
  attacker: "phi3"
  judge: "phi3"
```

## Safety Evaluation

The Safety Judge classifies model behavior into explicit outcomes such as:

- `SAFE_REFUSAL`
- `JAILBREAK_SUCCESS`
- `PROMPT_INJECTION_SUCCESS`
- `SENSITIVE_INFO_DISCLOSED`
- `HARMFUL_CONTENT_GENERATED`
- `ROLE_PLAY_COMPLIANCE`
- `CODE_INJECTION_SUCCESS`
- `DENIAL_OF_SERVICE_SUCCESS`
- `LOGICAL_REASONING_FAILURE`
- `EVALUATION_ERROR`

This produces structured results that can be stored alongside the attack history and used to assess whether a defensive change actually improved behavior.

## Reports

Each simulation can generate:

- a machine-readable JSON report containing the final hardened prompt and simulation history
- a Markdown report summarizing the simulation and its outcomes

These reports make experiments easier to inspect, compare, and reproduce.

## Design Highlights

### Adaptive Red Teaming

The Red Team agent first cycles through known attack prompts. Once those are exhausted, it escalates through a playbook of creative strategies including role-play, hidden instructions, logical reasoning traps, and authoritative or urgent framing.

### Defensive Prompt Evolution

When an attack succeeds, the Blue Team receives the failed interaction and generates a revised system prompt. PromptShield then tests that new prompt against the same attack and only adopts it when the validation succeeds.

### Local-First Architecture

The project is designed around local models served by Ollama, allowing safety experiments to run without requiring a hosted LLM API for the target, attacker, or judge roles.

## Why PromptShield?

A static jailbreak test can tell you whether a model fails against a particular prompt. PromptShield explores a more realistic engineering question:

> **Can a model's defenses adapt when an attacker changes tactics?**

By combining adversarial generation, automated evaluation, defensive prompt evolution, and validation, the project provides a compact framework for experimenting with iterative LLM safety testing.
